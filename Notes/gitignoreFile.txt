~> .gitignore
    - A special file used by Git to specify which files and folders should be ignored.
    - Ignored files are not tracked, staged, or committed by Git.
    - Mainly used for temporary files, build files, dependencies, logs, cache, and secrets.

~> How it Works
    1. Git reads the .gitignore file from top to bottom.
    2. If a file matches a rule, it is ignored.
    3. Later rules can override earlier rules using !.
    4. Only affects untracked files.
    5. Already tracked files remain tracked until removed from Git.

~> Where to Place .gitignore
    1. Create the .gitignore file in the root directory of your Git repository (same level as the .git folder).
    2. Git automatically looks for and reads .gitignore files when checking which files should be tracked or ignored.
    Example:
        MyProject/
            ├── .git/
            ├── .gitignore
            ├── src/
            ├── package.json
            └── README.md

~> When Git Uses .gitignore
    1. Whenever Git scans the working directory (e.g., during git status, git add ., git commit, etc.), it checks .gitignore rules first.
    2. Before adding untracked files to the staging area, Git compares them against .gitignore patterns and skips the matching files/folders.

~> Comments (#)
    - Used to write notes inside .gitignore.
    Example:
        # Ignore log files

~> Ignore a Specific File
    - Write the file name.
    Example:
        secret.txt

~> Ignore a Specific Folder (/)
    - Add / after the folder name.
    Example:
        node_modules/

~> Ignore by Extension (*)
    - * matches any number of characters.
    Example:
        *.log
    Matches:
        error.log
        debug.log

~> Ignore Files Starting With
    Example:
        temp*
    Matches:
        temp
        temp1
        temporary

~> Ignore Files Ending With
    Example:
        *temp
    Matches:
        mytemp
        newtemp

~> Single Character Match (?)
    - ? matches exactly one character.
    Example:
        file?.txt
    Matches:
        file1.txt
        fileA.txt
    Not:
        file10.txt

~> Character Range ([])
    - Matches one character from a set or range.
    Example:
        file[1-3].txt
    Matches:
        file1.txt
        file2.txt
        file3.txt

~> Negation (!)
    - Re-includes an ignored file.
    Example:
        *.txt
        !notes.txt
    Result:
        notes.txt → Tracked
        other.txt → Ignored

~> Root Directory Match (/)
    - Match only from repository root.
    Example:
        /config.json
    Matches:
        project/config.json
    Not:
        project/src/config.json

~> Recursive Match (**)
    - Matches any number of directories.
    Example:
        **/*.log
    Matches:
        error.log
        src/error.log
        app/src/error.log

~> Ignore Everything (*)
    Example:
        *
    Result:
        All files ignored

~> Ignore Everything Except Specific Files
    Example:
        *
        !README.md
        !.gitignore

~> Common Patterns
    Ignore Logs:
        *.log
    Ignore Environment Files:
        .env
    Ignore Dependencies:
        node_modules/
    Ignore Build Files:
        dist/
        build/
    Ignore Cache:
        .cache/

~> Important Note
    If a file is already tracked:
        secret.txt
    Adding this:
        secret.txt
    will NOT ignore it.
    Remove from tracking:
        git rm --cached secret.txt
