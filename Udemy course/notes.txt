~> Key Terms:
    - Add:
        To state changes, to add the modified files to the staging area, marking them as ready to be committed.
    - Commit:
        A commit is a snapshot of your project's state at a specific point in time, including the changes made to files and a descriptive message about what was changed. 
    - Commit changes and Descriptive Commit messages:
        to create a new commit with a message explaining what changes were made.
    - Track state:
        By creating a commit, you are essentially saving the current state of your project so you can revert back to it if needed or continue working on top of it. 
    - Remote:
        In Git, "remote" refers to a copy of your repository hosted on a server, like GitHub. 
    - Branch:
        A branch is a separate line of development within a repository, allowing you to work on different features without affecting the main codebase.
    - Fetch:
        When you fetch changes from the upstream, all new data from commits that were made since you last synced with the remote repository is downloaded into your local copy. This new data is not integrated into your local files, and changes are not applied to your code.
        Fetched changes are stored as a remote branch, which gives you a chance to review them before you merge them with your files.
    - Update:
        Use update if you need to sync a specific branch with its remote tracked branch. This is a convenient shortcut for fetching and subsequently applying changes to the selected branch.
    - Pulls:
        If you need to get changes into the current branch from another branch instead of its remote tracked branch, use pull. When you pull, you not only download new data, but also integrate it into your local working copy of the project.
        To pull changes from a remote branch:
            git pull origin <branch-name>. 
    - Rollback:
        To reset the changes back to the previous commit.
        To rollback to a previous commit:
            git reset --hard <commit-hash>. 


~> Brief Working (How to do it):
    1. Make changes to your project files:
        Edit the necessary files in your working directory. 
    2. Stage changes:
        Use git add to add the modified files to the staging area, marking them as ready to be committed. 
    3. Commit changes:
        Use git commit -m "Descriptive message" to create a new commit with a message explaining what changes were made. 
    4. Push to remote branch:
        Use git push origin <branch-name> to send your commit to the specified branch on the remote GitHub repository.

*~> For file system checkup:
    Purpose
        - Detect Corrupted Objects: Identifies corrupted blobs, commits, trees, or tags in your repository.
        - Identify Broken Links: Reports dangling references (e.g., objects no longer connected to any branch or tag).
        - Verify Integrity: Ensures that all objects and their relationships in the .git directory are intact.
        - Help Debug Issues: Useful for troubleshooting issues like repository corruption or missing data.
    When to Use
        - After encountering errors like missing objects or lock files.
        - To check repository health after a system crash or unexpected interruption during Git operations.
        - If your repository behaves abnormally (e.g., commits not showing, missing files).
    Outputs
        - Healthy Repository:
            Checking object directories: 100% (256/256), done.
            Checking objects: 100% (1000/1000), done.
        - Corruption Detected:
            missing blob 9a2e56a8cd12bb8cd5af...
            dangling commit 4b825dc642cb6eb9...
    Fixing 
        - Dangling Objects: Usually safe to ignore unless you need them (e.g., unreferenced commits). To clean them:
            git gc --prune=now
        -Corrupted Objects: You might need to restore from backups or fetch the missing data from a remote repository.
    command:
        git fsck

*~> Fixing Dangling Objects:
    git gc Stands for Git Garbage Collection.
    It cleans up unnecessary files and optimizes the local repository.
    Normally, Git keeps unreachable objects for a grace period (default: 2 weeks) before removing them.
    The --prune=now option tells Git to remove all unreachable objects immediately, without waiting for the grace period.
    command:
        git gc --prune=now

~> To remove Untracked files
    It’s important to emphasize that untracked files do no harm; you could just leave them where they are.
    Removing them makes your working directory cleaner and more organized.
    Git clean is a somewhat lesser-known git command. You can use it to clean all untracked files at once.
        By using Command:
            git clean -f
        You’ll get a result like this:
            Removing file.txt
    When you use the -n parameter, git clean displays what would happen but doesn’t actively remove anything.
    It's a simiulation cleaning of untracked files (a simulation not real).
        By using Command:
            git clean -n
        The result is this:
            Would remove file.txt
    The -i parameter is for interactive. It displays a menu with options you can use for cleaning.
    It's an Interactive cleaning.
        By using Command:
            git clean -i
        It will display all the files and below that a commands menu asking how to remove files and ask for option number .i.e, 1/2/3/4/5/6.
            Would remove the following items:
                <file1.type1> <file2.type2>
            *** Commands ***
                1: clean
                    (if we press 1 or c it removes all files)
                2: filter by pattern
                    (if we press 2 or f it filters a particular type of filename patterns, if we press 2 or f then add filter *.md, then i get all files not haveing.md in their names and we can decide what to do with them after it)
                3: select by numbers
                    (if we press 3 or s gives a labelled menu and for option number to delete that particular file)
                    (to select multiple files enter s then comma seperated option numbers i.e, 1,2,etc)
                4: ask for each
                    (if we press 4 or a it asks [y/N]? for each file)
                5: quit
                    (if we press 5 or q git will display a message "Bye" wihtout harming files)
                6: help
                    (if we press h or 6 it displays a useful yet concise help screen)
    However, if you want to remove them, you can use the following command:
    command:
    git rm --cached <filename>
